## Ruling

Quoted from index.md:

> **7. Bundle pins.** The inventory generator **throws** on a component ref that
> is malformed, names no `stacks/<type>/<slug>/pack.yaml`, or pins a version
> differing from that pack's `version`; `@generated` refs are skipped. The
> ruling is written into `pack-format.md`'s Rules section beside "a pack is
> copied, never referenced in place".
>
> **13. Inventory failure tests.** A temp-root fixture mirroring
> `plugins/stackgen/stacks/` plus a minimal `assets/kinds.md`, driven through
> the existing `readInventory(repoRoot)` export; no new exports.

Why it is a throw and not a rendered row: the module doc (lines 24–27) already
rules that a pack or bundle missing a required field, or a `kind` no heading
defines, fails generation outright rather than rendering a wrong row. A pin that
resolves to nothing, or to a version the pack no longer carries, is the same
class — the inventory would otherwise advertise a composition the materializer
cannot copy, and `stackgen-sync` diffs on exactly that version.

## Edits

1. **`scripts/src/inventory.ts`** — in `readInventory` (77–97), after the two
   `assertKind` loops, call a new `assertComponents(packs, bundles)`:
   - for each bundle, for each entry of `components`: match
     `/^([a-z0-9-]+)\/([a-z0-9-]+)@(.+)$/`; no match → throw
     `` `${BUNDLES_DIR}/${slug}.md` component ref "<entry>" is not <type>/<slug>@<version> ``;
   - version `generated` → skip (a first-class outcome, `pack-format.md`);
   - find the pack with that `type` and `slug`; none → throw
     `… pins "<entry>" but there is no ${STACKS_DIR}/<type>/<slug>/pack.yaml`;
   - `pack.version !== version` → throw
     `… pins "<entry>" but that pack.yaml is at version <pack.version> — a bundle is the recorded composition, so bumping a pack means re-pinning every bundle that names it`.
   - `Pack` already carries `type`, `slug` and `version` (lines 46–56, 131–135);
     no reader change is needed.
2. **`scripts/src/inventory.ts`** — the module doc at 24–27: list the new throw
   conditions beside the two existing ones.
3. **`scripts/src/inventory.test.ts`** — add a `describe("component refs")`
   using a temp root built with `mkdtempSync`, containing
   `plugins/stackgen/assets/kinds.md` with one heading in the shape `readKinds`
   parses (see `readKinds` at 100–113 for the exact regex), one
   `plugins/stackgen/stacks/<type>/<slug>/pack.yaml` carrying `name`, `summary`,
   `version`, `kind`, and one `plugins/stackgen/stacks/bundles/<b>.md` with
   frontmatter `name`, `kind`, `axis`, `components`. Four cases:
   - a ref pinned to the pack's version resolves and `readInventory` returns;
   - a ref naming a slug with no `pack.yaml` throws, message naming the bundle
     and the ref;
   - a ref pinned to a version differing from `pack.yaml` throws, message naming
     both versions;
   - an `@generated` ref with no pack directory returns cleanly. Keep the
     existing real-repo tests untouched; the corpus resolves today (57 pinned
     refs, 11 `@generated`, 0 mismatches), so they stay green.
