Four phases, one slash command each.

Everything up to the blueprint is done in full before planning; plan halts on a partial coverage stamp. While you author, Claude asks one question at a time. While it executes, it runs unattended and never merges until you approve.

Read the command reference

Product/vwf:product

Pin the outcome contract: the problem, the users, measurable goals, and the order to build in. Everything downstream must trace to it.

Blueprint/vwf:blueprint

Keep an always-current blueprint of the whole product, organized by flow, with entities as the data contracts under them, closed by a whole-product coherence review.

Plan/vwf:plan

Diff the blueprint against the real code for one slice, planning its unbuilt dependencies as their own chained plans first, and write the delta to apply.

Execute/vwf:execute

Implement the plan autonomously under strict TDD, with code review, security review, E2E acceptance and UX conformance, behind one final merge gate.

Install

One command

Registers the marketplace and installs the workflow. stackgen, its one dependency, comes with it.

pnpx @virajp.dev/claude-plugins --all

Or Claude Code's own commands

The wrapper sequences these two. The marketplace manifest is this repo's main branch either way.

claude plugin marketplace add virajp/claude-plugins claude plugin install vwf@virajp-plugins

Restart Claude Code afterwards, then run /vwf:doctor. Nothing is checked at install time.

Know this before you install.

vwf is deliberately heavyweight. Some of what it needs is a real adoption blocker rather than a preference.

Built for the 1-million-token window

The orchestrator holds the blueprint, the plan, the registry and each subagent's output at once. The standard window will degrade or overflow on a real cycle.

Runs opus where judgment decides

An execute cycle runs several opus subagents per step with fix loop-backs. Expect a meaningful token cost per slice. This is not a cheap workflow.

Expects a testable, registry-described project

Execute enforces TDD and a coverage gate, and each slice maps to a project in a registry you author first. It will not operate on an ad-hoc folder.

Five binaries on your PATH

mise, graphify, uv, pnpm and rtk. Nothing checks this at install time, and doctor does not cover all five. Install them rather than relying on it.
