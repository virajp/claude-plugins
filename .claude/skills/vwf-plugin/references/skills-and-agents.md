# vwf's skills and agents

The three artifact families under `plugins/vwf/`: the workflow skills, the
subagents they delegate to, and the auto-applying doctrine skills. **Each
SKILL.md and agent file is authoritative for its own behavior** — the tables
here are an index, not a second copy.

- `skills/` (workflow) — the `/vwf:` workflow skills (each
  `skills/<name>/SKILL.md`), implementing the Product → Blueprint → Plan →
  Execute model. Most are slash- **and** model-invocable because **other skills
  delegate to them by name**; three are **user-only**
  (`disable-model-invocation: true`) — `mockups`, `recall` and `verify`;
  `design-system` is model-invocable though nothing calls it, and so is
  `execute`, which asks new session or this one when the model starts it; five —
  `init`, the three import adapters `import-design-system`, `import-screens`,
  `import-conversations`, and `plan-management` — are **skill-invoked**,
  `user-invocable: false` beside `disable-model-invocation: false` and no
  `paths:`, so each is hidden from the `/` menu and reached only by the skill
  that owns its seam (`/vwf:setup`, `/vwf:design-system`, `/vwf:screens import`,
  `/vwf:feedback canvas`, and the two planners plus `execute` — or a session,
  when the user asks in prose to archive a folder or list the queue —
  respectively) — see Invocation policy below. **Each SKILL.md is the
  authoritative description of its own behavior**; the table below is an index,
  not a second copy — the previous prose version of it drifted twice in a single
  session before being cut.
