# Android — R8

R8 shrinks, optimizes and obfuscates the release build. It is on for every
release build of an app, and the release build is what the E2E tests run
against before a release — a keep rule that is missing breaks only there.

## Configuration

```kotlin
buildTypes {
    release {
        isMinifyEnabled = true
        isShrinkResources = true
        proguardFiles(
            getDefaultProguardFile("proguard-android-optimize.txt"),
            "proguard-rules.pro",
        )
    }
}
```

`proguard-android-optimize.txt` is the default file; never the non-optimizing
one. R8 runs in full mode by default on current AGP; a dependency that breaks
under it is fixed with a keep rule, not by turning full mode off.

## Keep rules

- A keep rule exists because something reaches code by name at run time:
  reflection, a class named in a resource or the manifest (AGP keeps those
  itself), JNI, or a serializer that reads fields reflectively.
- Each rule keeps **the one class or member** that needs it, with a comment
  naming the reason. A `-keep class com.example.** { *; }` disables shrinking
  for a package and hides the next real problem.
- Prefer libraries that need no rules: kotlinx.serialization and code-generated
  DI and database layers ship or generate their own.
- A library module ships the rules its consumers need in `consumer-rules.pro`,
  declared with `consumerProguardFiles`. It does not minify itself — the app
  that consumes it does, once, over everything.

## Stack traces

Obfuscated traces are mapped back with the `mapping.txt` of the exact build.
The release pipeline archives it with the artifact; a crash report without its
mapping is unreadable.

## Verifying

Run the instrumented tests against the release variant
(`test:e2e --variant release` once the managed device runs a release-signed
test build) before a release, and read the R8 output for `Missing class`
warnings — each is either a rule to add or a dependency to drop.
